# دیدار · ترتیب تکمیل UI پیش از اتصال سرویس‌ها

تصمیم ۲۰۲۶-۰۹-۲۴: ظاهر عمومی دیدارگلد مرجع طراحی است؛ HTML کلیک‌پذیر مرجع مسیرها و حالت‌های تعامل. صفحه‌ها و وضعیت‌ها ابتدا در پوستهٔ چهارزبانه ساخته و بازبینی می‌شوند، سپس هر جریان با API و دادهٔ معتبر فعال می‌شود. سند ۱۰۵ فرایندی مالکیت و معنای کسب‌وکار را مشخص می‌کند. دادهٔ ساختگی نباید در پوسته مانند واقعیت نمایش داده شود.

نمای کامل HTML مرجع در `apps/storefront/public/didar/interactive-preview.html` نگه‌داری و از `/fa/my-didar/preview` (یا `/ar`, `/en`, `/fr`) درون پوسته باز می‌شود. این راه برای دیدنِ فوری همهٔ تعامل‌های موجود در HTML است؛ iframe به‌صورت sandbox بدون دسترسی به origin اصلی اجرا می‌شود، بنابراین دادهٔ پیش‌نمایش از حساب و API واقعی جداست و ممکن است ذخیرهٔ محلی یا مکان‌یابی داخل آن کار نکند. انتقال تدریجی صفحه‌ها از این فایل به کامپوننت‌های بومی Next.js و تأیید بصری جزئیات هنوز لازم است.

ورودی هر خدمت در `/[locale]/my-didar/[role]/[service]` همان پیش‌نمایش را با زبان و نقش انتخاب‌شده در صفحهٔ ورود نمونه باز می‌کند؛ نام خدمت در پوسته مشخص است، اما برنامهٔ HTML هنوز صفحهٔ داخلی هر خدمت را بعد از ورود باید از منوی خود انتخاب کند. این مسیریابی عمیق به جریان واقعی نیست.

## معیار تحویل UI

هر مسیر باید حالت‌های خالی، بارگذاری، خطا، در انتظار تأیید، تأییدشده و بدون مجوزِ مرتبط خود را پوشش دهد؛ در `/fa`, `/ar`, `/en`, `/fr` جهت متن، فونت و چیدمان درست باشد و در موبایل کار کند. برای UID/SKU و عددها جهت مستقل اعمال شود. دکمه‌ای که سرویس سروری ندارد باید وضعیت غیرفعال/«در حال اتصال» روشن داشته باشد؛ هیچ ثبت، قیمت، موجودی، سفارش، گارانتی، اصالت یا ماندهٔ مالی به‌صورت نمایشی به کاربر نسبت داده نشود.

## مرز دادهٔ محصول

فهرست ۶۷تایی snapshot از صفحهٔ عمومی دیدارگلد است؛ نام، تصویر و پیوند منبع واقعی‌اند، اما فقط ۲۰ صفحهٔ جزئیات بازبینی شده است. برای ۴۷ مورد دیگر جزئیات اضافی نشان داده نمی‌شود. این داده هنوز Product/Variant قابل خرید Medusa نیست؛ ورود نهایی نیازمند شناسه، SKU و دادهٔ تجاری تأییدشده است.

ترتیب کار پس از این برش: بازبینی بصری پوسته و فایل تعاملی در مرورگر واقعی → انتقال صفحات مشتری و خرده‌فروش از HTML به کامپوننت‌های بومی با حالت‌های درخواست/پیگیری → تأمین‌کننده/بنکدار → صفحه‌های داخلی و بازبینی چهار زبان/موبایل → اتصال API هر مسیر و آزمون دسترسی. وجود مسیر HTML به‌تنهایی به معنی تکمیل این انتقال نیست.
