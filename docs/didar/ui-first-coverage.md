# دیدار · ترتیب تکمیل UI پیش از اتصال سرویس‌ها

تصمیم ۲۰۲۶-۰۹-۲۴: ظاهر عمومی دیدارگلد مرجع طراحی است؛ HTML کلیک‌پذیر مرجع مسیرها و حالت‌های تعامل. صفحه‌ها و وضعیت‌ها ابتدا در پوستهٔ چهارزبانه ساخته و بازبینی می‌شوند، سپس هر جریان با API و دادهٔ معتبر فعال می‌شود. سند ۱۰۵ فرایندی مالکیت و معنای کسب‌وکار را مشخص می‌کند. دادهٔ ساختگی نباید در پوسته مانند واقعیت نمایش داده شود.

نمای کامل HTML مرجع در `apps/storefront/public/didar/interactive-preview.html` نگه‌داری و از `/fa/my-didar/preview` (یا `/ar`, `/en`, `/fr`) درون پوسته باز می‌شود. مسیرهای هر نقش اکنون کامپوننت بومی Next.js دارند؛ HTML مرجع برای مقایسهٔ جریان‌های باقی‌مانده است. داده‌های بومی نمونه در localStorage همان مرورگر ذخیره می‌شوند و به حساب یا API واقعی ارتباط ندارند.

بازبینی بصری ۲۰۲۶-۰۹-۲۴ نشان داد پوستهٔ اولیه حتی در صفحهٔ خانه به مرجع نزدیک نبود. نسخهٔ بعدی هدرِ روی فیلم، فیلم تمام‌صفحه، منوی کشویی، جست‌وجوی تمام‌صفحه، دسته‌ها، آثار منتخب، قاب‌های ادیتوریال، کالکشن‌ها و چیدمان کاتالوگ و جزئیات محصول را بر اساس خود `didargold.ir/fa` بازسازی کرد. این بازسازی هنوز آزمون دیداری نسخهٔ اجراشده در مرورگر، هم‌ارزی همهٔ مسیرهای اطلاعاتی و همهٔ افکت‌ها و بررسی ۱۶ حالت زبان/اندازهٔ صفحه را ندارد؛ عنوان «کپی کامل» یا «برابری پیکسلی» برای آن درست نیست. تصویرها و فیلم صفحهٔ عمومی فعلاً از آدرس‌های مرجع بارگذاری می‌شوند؛ برای استقلال نهایی باید دارایی‌ها با مجوز مالک در پروژه میزبانی شوند.

«مای دیدار» در هدر منوی انتخاب چهار نقش را باز می‌کند. پس از انتخاب نقش، صفحهٔ ورود همان نقش باز می‌شود؛ اگر ایمیل نمونه یافت نشود، کاربر می‌تواند درخواست عضویت نمونه ثبت کند و سپس وارد پیش‌نمایش شود. لینک مستقیم هر خدمت در `/[locale]/my-didar/[role]/[service]` نیز تا ورود نمونه به میزکار دسترسی UI نمی‌دهد. ورود، خروج و ثبت‌نام صرفاً localStorage و برای بازبینی ظاهرند؛ احراز هویت واقعی و حفاظت سروری هنوز ساخته نشده‌اند. فرم‌ها و وضعیت‌های دیگر برای بازبینی UI تعاملی‌اند؛ تغییر منو داخل همان صفحه انجام می‌شود و آدرس هر زیرمنوی اضافی هنوز تکمیل نشده است.

مسیر `/` و پوستهٔ زبان‌های دیدار برای نمایش به بک‌اند یا منطقهٔ فروش مدوسا وابسته نیستند؛ مسیرهای قدیمی فروش همچنان کنترل منطقهٔ فروش خود را نگه می‌دارند.

## معیار تحویل UI

هر مسیر باید حالت‌های خالی، بارگذاری، خطا، در انتظار تأیید، تأییدشده و بدون مجوزِ مرتبط خود را پوشش دهد؛ در `/fa`, `/ar`, `/en`, `/fr` جهت متن، فونت و چیدمان درست باشد و در موبایل کار کند. برای UID/SKU و عددها جهت مستقل اعمال شود. دکمه‌ای که سرویس سروری ندارد باید وضعیت غیرفعال/«در حال اتصال» روشن داشته باشد؛ هیچ ثبت، قیمت، موجودی، سفارش، گارانتی، اصالت یا ماندهٔ مالی به‌صورت نمایشی به کاربر نسبت داده نشود.

## مرز دادهٔ محصول

فهرست ۶۷تایی snapshot از صفحهٔ عمومی دیدارگلد است؛ نام، تصویر و پیوند منبع واقعی‌اند، اما فقط ۲۰ صفحهٔ جزئیات بازبینی شده است. برای ۴۷ مورد دیگر جزئیات اضافی نشان داده نمی‌شود. این داده هنوز Product/Variant قابل خرید Medusa نیست؛ ورود نهایی نیازمند شناسه، SKU و دادهٔ تجاری تأییدشده است.

ترتیب کار پس از این برش: بازبینی نسخهٔ اجراشده در مرورگر واقعی → تکمیل همهٔ حالت‌های HTML شامل پاسخ استعلام، پیش‌فاکتور، سفارش، ثبت شکایت، فعال‌سازی گارانتی خرده‌فروش و منوهای زیرحساب → صفحه‌های داخلی و بازبینی چهار زبان/موبایل → اتصال API هر مسیر و آزمون دسترسی. این برش تنها انتقال بخشی از UI است و هم‌ارزی کامل HTML هنوز تأیید نشده است.
